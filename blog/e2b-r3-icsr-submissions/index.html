E2B(R3) ICSR submissions start with a complete case

QORO Team · 23 October 2026 · about 6 minutes

E2B(R3) ICSR submission is the sentence sponsors use when they mean "the electronic file the authority will accept." ICH E2B(R3) is a message standard. An individual case safety report is the medical and administrative content. Submission is the act of sending a valid message to the authority. Those are three layers. Tools that advertise E2B(R3) sometimes only mean they can export a file shaped like the standard. A file that never leaves the building is not a submission.

What the message is for

Regulators moved individual case exchange off paper and off older E2B releases onto E2B(R3). The message carries reporter, patient, reaction, drug, and narrative sections in a fixed structure so a receiving system can read them. FDA's electronic submissions gateway, and the equivalent paths in other regions, are how the message travels. The gateway checks that a sender is allowed to send. It does not check that the causality call was wise.

The case is the product. The XML is the packaging.

E2B(R3) validation will reject a message with missing required elements. It will not reject a message whose serious box was guessed from a subject line. The elements that make a case worth sending are the same ones intake is supposed to capture, plus the decisions a qualified person has made:

  • Reporter and patient, identifiable enough for a valid case, with the privacy limits your process already uses.
  • Suspect product, dose, and dates.
  • Reaction in the reporter's words, and a MedDRA term a coder is willing to stand behind.
  • Seriousness, expectedness against a named reference document, and causality.
  • The receipt date that starts the 7-day or 15-day discussion, if this is an expedited case.
  • A narrative that matches the structured fields. When they disagree, the authority sees both.

Teams stall on the packaging because the case is still in email. Buying a gateway login does not create the case. The inbox is still the bottleneck at a lot of small biotechs.

Who actually sends it

A company that runs Oracle Argus, ArisGlobal LifeSphere, or Veeva Vault Safety often sends from that system, or from a safety CRO that runs one of them. That is a reason to have the database, and it is also a reason not to pretend an intake workspace is the database. AE Connect does not configure those products and does not hand them a case. If they are your system of record, someone still types or reconciles the official case there before the message exists.

A sponsor that has outsourced submissions should be able to name the vendor, the account, and the person who confirms a file was acknowledged. "We use a gateway" is not a control. The checklist is the blunter version of that question.

FAQ

What is an E2B(R3) ICSR submission?

E2B(R3) is the ICH standard for the electronic message that carries an individual case safety report. An E2B(R3) submission is that message, validated and sent to an authority such as FDA through the path the authority requires. It is the transport format of a case, not the medical judgment inside the case.

Does AE Connect submit E2B(R3) files?

No. AE Connect does not create E2B(R3) XML, does not connect to an ESG or other gateway, and does not transmit ICSRs. It drafts a human-reviewed assessment from the source narrative. A safety database, a CRO, or a publishing tool sends the file.

What has to be in the case before an E2B(R3) file is worth building?

A valid case: identifiable reporter, identifiable patient, suspect product, and event, plus the seriousness, coding, causality, and expectedness decisions a reviewer has accepted. A narrative still sitting in a PDF will fail validation or, worse, pass validation with the wrong facts.

Where should a small sponsor start on E2B(R3)?

Read the intake and the deadline notes, then use a checklist for the operational pieces: accounts, identifiers, and who actually sends the file. AE Connect is only the intake and draft step. The longer guide and the checklist on this site cover the filing side.
